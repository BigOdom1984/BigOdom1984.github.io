How a project works

  1. Discovery: confirm goals, audience, pages, apps, content, integrations and budget.
  2. Proposal: agree the initial payment, deliverables, milestones, revision allowance and acceptance criteria.
  3. Build: create the site using approved reusable modules and an isolated customer configuration.
  4. Review: test desktop, tablet and mobile layouts, accessibility, speed, security and integrations.
  5. Launch: connect the verified domain, publish, test forms and integrations, and hand over access.
  6. Support: maintain backups, dependencies, content and approved updates under the selected support plan.

Support plans

Essential

For routine maintenance, dependency updates and basic monitoring within the agreed monthly allowance.

Business

For regular content changes, integration checks, backups and a defined response target.

Priority

For more frequent updates, priority incident triage and expanded maintenance hours.

Custom SLA

For critical services requiring negotiated response windows, escalation and operational responsibilities.

Exact support hours, response windows, uptime targets and incident coverage are written into each agreement. No 24/7 or guaranteed uptime claim is made unless it is staffed, measured and contracted.

Built around reusable modules

When appropriate, the website can consume the CashDublo central API for approved navigation, product records, membership display and website configuration. Each customer's content and settings remain isolated. Public pages keep a static fallback so a temporary API outage does not make the website disappear.

The customer control application and full hosted API platform are being developed in stages. Features are included in a project only after implementation and verification.
