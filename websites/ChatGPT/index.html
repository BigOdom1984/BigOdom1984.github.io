Back ends

The machinery behind the doors - the production server and its offline twin.

The Production Server

Live · the doors

The back end itself: a row of doors, each doing one job - updates, the AI, licenses, location, voice credits, and the store. It is live now; its newest build, the store doors, is being switched on.

  • One door file can hold many doors, so the plan's door limit is never the boss
  • Service switches let the owner turn a door off in plain words
  • The offline copy below mirrors it for testing

Why have it: the apps never talk to a page - they talk to doors, and doors do not need to be pretty, they need to answer.

The Offline Server

The Production Emulator · testing

The same server, copied to run on Cash's own machines as a background service. Desktop apps on the same computer connect to it for testing - same doors, same shapes, test keys only. Production has no same-machine door.

  • Runs with the machine, no window open
  • The full server snapshot rides inside it, refreshed as the server grows

Why have it: every change is proven at home before it ever faces the live doors.

The online app store

The store CashDublo is building - its own shelf, its own delivery, no middleman.

The App Store

Being built · the shelf

CashDublo's own store: the apps on one shelf, sold and delivered by the house itself. The store's back end is built; the shelf fills as the apps are placed on it.

  • One shelf for every CashDublo app
  • Licenses granted and checked by the server's license doors

Why have it: the house sells its own work in its own store, on its own terms.

The Store Back End

Built · switching on with the server update

Three doors do the store's work: the catalog door shows the shelf, the package door delivers an app in pieces so a drop never loses the whole download, and the master ledger records every delivery until it lands.

  • Catalog: the shelf, computed from the real packages - sizes and contents never typed by hand
  • Package: delivery in pieces, each piece checked
  • Ledger: every delivery written down until it is complete

Why have it: delivery that does not fail quietly - if a download drops, the ledger knows exactly where it stopped.

The Store App

In the build queue · Android

The store as an app on the phone - the same shelf and the same doors, carried in a pocket. It stands in the build queue behind the training app's Mac face, the password vault's Android shell, and Darkweb Surfer.

Why have it: the store where the apps live - on the phone itself.
